# bid-company-evaluator · 投标公司符合性评估器

拿一份招标 / 磋商 / 询价文件，对**任意一家**投标公司做资质评估、符合性评估与标准评估，
逐条判定是否符合招标文件的要求，给出「出局 / 待定 / 通过」结论与详细评审得分区间。

**它不参与投标**：不编写投标文件、不代填响应表、不生成报价、不预测报价分与排名。

---

## 它解决什么

投标前要回答一个问题：**这个项目我们能不能投、投了会死在哪、能拿多少分。**
靠人翻文件有两个杀手：

| 杀手 | 后果 | 这个工具怎么防 |
| --- | --- | --- |
| **虚报** | 投标里叫提供虚假材料，后果是废标 + 不良行为记录，不是扣几分 | 强制企查查取证 + 三道甄别。实测：查到 23 个软著，与招标限定领域相关的 **0 个** → 判 0 分，不是 5.75 分 |
| **漏项** | 「未标注符号的条款」扫符号扫不到，是一整块盲区 | 无符号条款也建分值池逐条登记。实测：25 条 / 10 分，全靠建池才找出来 |

---

## 三条评估线

| 线 | 判什么 | 不满足的后果 |
| --- | --- | --- |
| **资质评估** `QUALIFICATION` | 主体资格、政策资格、特定资格、信用记录 | 出局 |
| **符合性评估** `CONFORMITY` | ★ 实质性要求、有效期、报价、签章、知识产权 | 判无效响应 |
| **标准评估** `SCORING` | 符号条款与无符号条款的扣分、加分项 | 扣分 |

判定值只有四个：**`PASS` 符合 / `FAIL` 不符合 / `UNKNOWN` 资料不足 / `NA` 不适用**。
`UNKNOWN` 必须写清缺哪一份具体材料——它和「不符合」是两回事，绝不能混。

## 快速开始

```bash
# 0 生成工作目录骨架（可选）
python scripts/init_work.py --out ./work

# 1 固化原文：docx/pdf → 带行号底稿 + 指纹 + 符号台账
python scripts/extract_tender.py 招标文件.docx 招标文件.pdf --out ./work --tag tender

# 2 企查查取证（由 Agent 调用 MCP 工具完成）→ work/company_profile.json
# 3 拆要求（S1）与逐条判定（S3）→ work/requirements.json / work/assessments.json

# 4 计算与门禁校验
python scripts/evaluate.py --requirements work/requirements.json \
                           --assessments  work/assessments.json \
                           --profile      work/company_profile.json --out ./work
python scripts/validate.py --work ./work --profile work/company_profile.json
```

`validate.py` 报 **ERROR 一律不许交付**。改完脚本跑 `python scripts/self_test.py`，须 6 项全绿。

## 关键设计

- **得分区间，不是一个数。** 下限 = 所有「资料不足」按不满足计；上限 = 按满足计。**区间越宽 = 资料缺口越大。**
- **扣分池是基准分，不是零起扣分。** 池内全满足即拿满 `declared_total`，不满足按项扣，扣完为止不为负。
- **加分项与扣分项必须分开。** 往下扣的是扣分项（`per_item`），往上加的是加分项（`max_score`，不进池）。混在一起条数、总分两处都会错。
- **零资料幻觉。** 公司事实只能来自企查查或用户指定的资料；没有材料一律 `UNKNOWN`，禁止推断、类比、常识补全。
- **确定性计算与语义判断分离。** 脚本只做扣分累加、区间、硬门槛推导这类确定性计算；语义判断由 Agent 落进 JSON，再由 13 条规则反向校验。
- **逐行台账，不做总量对账。** 「共 N 条 ≠ 符号出现 N 次」——评分规则描述句自己就含符号。台账键是 **(符号, 行号)**。

## 门禁规则

| 规则 | 拦什么 |
| --- | --- |
| R1 / R2 | 每条要求都有判定；判定值合法；不出现凭空判定 |
| R3 | `UNKNOWN` 必填缺什么 |
| R4 | 硬门槛不满足 → 结论必须是「出局」（双向校验） |
| R5 / R6 / R13 | 分值池乘法闭合、条数核对、禁止凭空估分、**总分闭合** |
| R7 | 得分区间不越界、不颠倒 |
| R8 / R11 / R12 | 证据编号可追溯；来源标注完整；**判「符合」必须挂证据** |
| R9 | 覆盖台账逐行闭合 |
| R10 | 原文引句必须与抽取文本对得上 |

## 实测数据（一份真实竞争性磋商文件）

- 拆出 **90 条**要求：资质 10 + 符合性 26 + 标准 54（扣分项 50 + 加分项 4）
- 判定：**符合 6 / 资料不足 81 / 不符合 2 / 不适用 1** → 结论「待定（资料不足）」
- 详细评审区间 **0.00 ~ 78.00 / 满分 90.00**
- 分值闭合：扣分池 `12×1.5 + 3×5 + 10×0.5 + 25×0.4 = 48`，加分项 `15+7+5+15 = 42`，**48 + 42 = 90**
- 门禁校验：**0 ERROR / 0 WARN**

81 条「资料不足」不是失败——公司只提供了企查查能查到的部分，平台运行数据、功能截图、现场演示、
合同关键页、等保备案、承诺函、实施方案这些企查查管不到。**不知道的就说不知道，这是设计，不是缺陷。**
