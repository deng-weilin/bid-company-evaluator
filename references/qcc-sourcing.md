# 企查查取证规范

公司事实的**主要取证渠道是企查查**。但"查到了"不等于"符合要求"，中间隔着三道甄别。

## 一、先锚定主体（不锚定不许往下查）

```
get_company_by_query(searchKey=公司全称)
```

- 返回**唯一精确匹配** → 拿统一社会信用代码，后续所有工具**传信用代码，不传公司名**。
- 返回**多候选** → 必须把候选列表完整展示给用户，等用户选定。**自动选排名第一是错误行为**，会对错误主体做尽调。
- 返回**未匹配** → 让用户核对名称（常见：曾用名、多字少字、"四川"vs"四川省"）。

拿到信用代码后，建议再跑一次 `verify_company_accuracy` 校验"名称 + 信用代码"二要素匹配。

## 二、必查工具清单

### 资质线（硬门槛，查不到就出局）

| 查什么 | 工具 | 能证明 |
| --- | --- | --- |
| 主体身份、成立、注册资本、行业、登记状态 | `get_company_registration_info` | 独立承担民事责任的能力 |
| 失信被执行人（在册） | `get_dishonest_info` | 信用记录硬门槛 |
| 严重违法失信名单（在册） | `get_serious_violation` | 信用记录硬门槛 |
| 经营异常名录（在册） | `get_business_exception` | 商业信誉 |
| 近三年行政处罚 | `get_administrative_penalty(date_from=三年前的日期)` | 三年内无重大违法记录 |
| 税收违法 / 税务异常 | `get_tax_violation` / `get_tax_abnormal` | 依法纳税 |
| 被执行人 / 限制高消费 | `get_judgment_debtor_info` / `get_high_consumption_restriction` | 履约能力风险 |
| 从业人数、社保参保人数 | `get_annual_reports` | 中小企业划型 + 社保记录 |

## 三、企查查查不到的（必须回头找公司要原件）

这些**不能靠企查查蒙**，查不到就是 `UNKNOWN`：

| 缺的东西 | 为什么企查查没有 | 向谁要 |
| --- | --- | --- |
| 平台运行数据（课程数、资源库、模型库） | 这是对方平台后台数据 | 公司后台截图 + 教育部公示 |
| 功能截图、现场演示 | 属于产品能力，非工商数据 | 公司提供演示 |
| 信息安全等级保护备案证明 | 在公安系统，不在工商库 | 公司提供等保备案证明 |
| 合同关键页（金额、服务内容、盖章页） | 企查查只有**中标公告**，没有合同 | 公司提供合同复印件 |
| 人员配置表、实施方案、售后服务方案 | 主观分材料，公司内部文件 | 公司编写 |
| 承诺函意愿 | 属于公司决策 | 问公司确认 |
| 审计报告 / 财务报表原件 | 企查查财务数据可能不全 | 公司提供 |
| **政府采购严重违法失信名单** | 在 ccgp.gov.cn，不在企查查库 | **必须另行上网查** |

⚠️ 最后一条是硬门槛且企查查覆盖不到。**不许因为"企查查没查到问题"就判信用记录符合要求**，必须单独查中国政府采购网并留截图。

### ccgp.gov.cn 查不到怎么办（实测）

`https://www.ccgp.gov.cn/search/cr/` 是**动态查询页**，用 WebFetch 抓回来只有页面框架和导航、没有查询结果——抓不到 ≠ 名单里没有。

正确做法（三选一，按顺序试）：
1. 用浏览器自动化打开查询页，输入企业全称，截图留存；
2. 让公司自己登录 ccgp.gov.cn 查，提供**带日期的截图**；
3. 以上都做不到 → 判 `UNKNOWN`，`missing` 里写明"需人工登录 ccgp.gov.cn → 政府采购严重违法失信行为记录名单 → 输入企业名称查询并留存带日期截图"。

**绝对不许**因为"网页抓不到"就当成"没有记录"。

## 四、三道甄别（这是最容易做错的地方）

### 甄别 1：相关性 —— 查到 N 条 ≠ 得 N 条的分

招标写"具有**虚拟仿真相关**软件著作权证书，每有一个得 0.25 分，最多 7 分"，就必须**逐个看软著名称**，判断哪些与"虚拟仿真"相关。

> **实测例**：某公司企查查查到 **23 个软著**，逐个核对名称后，与招标限定领域相关的为 **0 个**。
> 若直接按 23×0.25 记 5.75 分，这份评估就是假的。

规则：
- 逐个看名称，不相关的剔除；
- 名称含糊、判不出相关性的 → 计入 `unknown_items`，不算 PASS；
- 明确有 N 条但**全部不相关** → 判 `FAIL`（这是明确的不符合，不是资料不足）。

### 甄别 2：去重 —— 公示和结果是同一个项目

企查查同一项目常出现两条记录：先是"**中选候选人公示**"，后是"**结果公告**/**中标公告**"。这是**一个业绩，不是两个**。

> **实测例**：某公司 10 条中标记录中，有 2 条属同一项目的公示+结果，实际独立项目 9 个。

规则：按"招采单位 + 项目主体名称 + 金额"去重，同一项目只记一次；金额完全一致或高度接近且时间相近的，重点核对。

### 甄别 3：主体一致 —— 关联公司的不算

证书、软著、业绩的**权属人必须是受评公司本身**。母公司、子公司、兄弟公司、同一实控人名下其他公司的，一律不算，除非招标文件明确认可。

可以用 `get_shareholder_info` / `get_actual_controller` / `get_executive_controlled_companies` 交叉核对关联主体，避免误算。

## 五、中小企业资格的一个隐藏雷

`registration_info` 里的**企业类型**字段要细看。

> **实测例**：某公司企业类型为"有限责任公司（**非自然人投资或控股的法人独资**）"——说明它有母公司。

《政府采购促进中小企业发展管理办法》规定：与大企业存在**直接控股、管理关系**的，不享受中小企业扶持政策。面向中小企业专门采购的项目，这是**出局级**风险。

处理：
1. 看到"法人独资""XX公司全资"→ 必查 `get_shareholder_info` 与 `get_actual_controller`；
2. 发现控股方是大企业 → 判 `FAIL` 或登记 `issues[]`（看原文表述），**不许默认放行**；
3. 查不清 → 判 `UNKNOWN`，missing 写"需确认控股股东规模及是否与大企业存在直接控股/管理关系"。

划型本身按**国标行业 + 从业人数 + 营业收入**判定。行业看 `国标行业` 字段，人数看 `参保人数`/`人员规模`，营收看 `get_financial_data`。

## 六、证据编号与来源标注

每一条企查查取到的事实都要进 `evidence_index`：

```json
{"id":"EV-001","name":"工商登记信息","source":"QCC",
 "tool":"get_company_registration_info","fetched_at":"2026-10-10",
 "key_facts":"成立2023-11-22；参保18人；软件和信息技术服务业","note":""}
```

- `source` 三选一：`QCC`（企查查）/ `WEB`（官网查询截图）/ `USER`（公司提供原件）。
- `source=QCC` **必须**填 `tool` 与 `fetched_at`。
- 判定条目的 `evidence` 只填 `evidence_index` 里存在的编号，由 R8 校验。
- `status=PASS` 的判定，`evidence` **不得为空**，由 R12 校验。

## 七、时效性

企查查数据更新频率为 T+0（工商、司法、招投标）或 T+1（软著、资质）。

- 评估报告里写清 `fetched_at`。
- 信用记录类（失信、严重违法、经营异常、处罚）**超过 7 天重查**，因为这是时点数据。
- 软著、资质类看 `有效期至` 字段，过期的不算数。

## 八、一句话总结

> 企查查负责**"有没有"**，甄别负责**"算不算"**，公司原件负责**"企查查管不到的部分"**。
> 三步少一步，评估结论就是编的。
