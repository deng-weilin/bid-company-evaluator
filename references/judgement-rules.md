# 判定口径

## 一、先说人话：黑话对照表

招标文件里全是黑话。写报告时**先用黑话定位，再用白话解释**，每一条判定后面跟一句"这对公司意味着什么"。

| 文件里的说法 | 白话 |
| --- | --- |
| 资格性审查 / 资格审查 | **能不能进门**。进门资格都没有，后面写得多好都白搭 |
| 符合性审查 | **交上来的东西算不算数**。格式、有效期、签字盖章、实质性要求有没有响应 |
| 实质性要求（★） | **碰了就死**。不响应直接判无效，没有补救机会 |
| 详细评审 | **进门之后比谁分高** |
| 综合评分法 | 既有打分又有价格，不是谁便宜谁赢 |
| 负偏离 | 做不到、做不到就扣分 |
| 无效响应 / 无效投标 | 白投了，连被比较的资格都没有 |
| 废标 / 终止采购 | 整个项目黄了，重来 |
| 中小企业声明函 | 一张自己声明"我是小企业"的纸，是政策照顾的入场券 |
| 承诺函 | 一张"我保证做到"的纸，盖章就生效，不用先拿证 |
| 履约保证金 | 中标后押在采购人那里的钱，干完活才退 |
| 澄清 / 说明 | 评审时评委提问，供应商限时书面回答 |

## 二、三条评估线

| 线 | 判什么 | 不满足的后果 | 对应文件章节 |
| --- | --- | --- | --- |
| **资质评估** | 主体资格、政策资格、特定资格、信用记录 | **出局**，连评审桌都上不了 | 第一章"供应商应具备的条件"、第五章"资格审查" |
| **符合性评估** | ★ 实质性要求、有效期、报价、签章、知识产权 | **判无效响应**，等于白投 | 第二章 2.4 系列、第三章带 ★ 的条款、第五章"符合性审查" |
| **标准评估** | 技术/服务标准的 ▲█● 扣分条款与加分项 | **扣分**，不致命但决定排名 | 第三章技术要求、第五章"评审细则及标准" |

**判定顺序不能反**：先资质 → 再符合性 → 最后标准。前一线没过，后一线的分数没有意义。报告里仍要列出后两线（供"补什么能救回来"用），但结论以资质线为准。

## 三、四个判定值（只有这四个，没有第五个）

| 值 | 什么时候用 | 硬性要求 |
| --- | --- | --- |
| `PASS` 符合 | 有材料、且材料对得上 | 必须挂证据编号 |
| `FAIL` 不符合 | 有材料、但材料明确对不上（数量不够、过期、主体不是本公司、完全没做） | 必须在 note 里写清对不上的具体点 |
| `UNKNOWN` 资料不足 | **拿不出材料**，或材料不足以确认 | 必须在 missing 里写清缺哪一份具体材料 |
| `NA` 不适用 | 该条对本公司不适用（如：非中小企业不适用小微优惠） | 必须在 note 里写清为什么不适用 |

### 最容易犯的错：把"资料不足"写成"符合"

- 公司说"我们有这个证"但没给扫描件 → `UNKNOWN`，不是 `PASS`。
- 公司说"我们平台大概有几百门课"但没给后台截图 → `UNKNOWN`。
- 招标文件要求"提供截图并加盖公章"，只有截图没盖章 → 看条款是否把盖章作为必要条件；条款未明确时判 `UNKNOWN` 并登记 issue，不自行取舍。

### 最容易犯的第二个错：把"不符合"写成"资料不足"

材料**明确**显示数量不够、过期、主体不符时，是 `FAIL`，不是 `UNKNOWN`。
例：招标要 5 个业绩，公司只给了 2 个合同 → 加分项判 `PASS` 并 `awarded=2`，**不是** `UNKNOWN`。

## 四、硬门槛 vs 软失分

```
is_hard_gate = true  →  不满足 = 出局 / 判无效
is_hard_gate = false →  不满足 = 扣分
```

判为硬门槛的（除非原文另有表述）：
1. 第一章"供应商参加本次政府采购活动应具备的条件"里全部条款；
2. 第五章"资格审查"表内全部条目；
3. 所有带 ★ 的条款；
4. 商务要求里的 ★ 项（服务期限、服务地点、支付方式、违约责任等）；
5. 串通响应、虚假材料等纪律性条款（第二章 2.7）。

判为软失分的：
1. ▲ █ ● 标记的技术条款（按分值池扣分）；
2. 无符号的技术/服务条款（按分值池扣分）；
3. 履约能力、类似业绩、实施方案等加分项。

## 五、得分怎么算（区间，不是一个数）

**两部分相加，别只算一半。**

```
详细评审得分 = 扣分池基准分 − 扣分  +  加分项实得
                 ↑ 全满足即拿满，按项扣，扣完为止不为负
```

- **扣分池**：每个池的 `declared_total` 是"这个池全满足能拿到的分"。不满足才扣 `per_item × 条数`。**不是从 0 往上加，是从满分往下扣。**
- **加分项**：`PASS` 记实际得分 `awarded`；`UNKNOWN` 下限记 0、上限记满分。
- **扣分要求**：`FAIL` 扣 `per_item × fail_items`；`UNKNOWN` 下限再扣一份，上限不扣。
- 报价分**不预测**。报价分要等开标后按基准价算，谁也不知道别人报多少。报告里写"不适用"。
- 输出是**区间**，不是精确分。区间越宽 = 资料缺口越大 = 这份评估越不可信。这句话必须写进报告。

> 真实教训：漏掉"扣分池基准分先给满"这一步，一份 90 分的卷子会算成 42 分满分，报告看起来只是"偏低一点"，没有任何规则会报错。
> 防它的是 R13（扣分池合计 + 加分项满分 == 总分）与报告里的"分数怎么来的"小表。

## 六、报告的边界（必须照抄进产出）

- 不编写投标文件、不代填响应表、不生成报价。
- 不预测报价分，不预测竞争对手得分与排名。
- 不对"资料不足"做任何推断。
- 结论仅供内部判断，不构成对评审结果的保证；最终以评审委员会认定为准。
